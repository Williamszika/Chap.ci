LA MÉTHODE — REMPLACER, JAMAIS MODIFIER
----------------------------------------
Je vous envoie le fichier complet, déjà correct. Vous le téléversez et vous le
renommez. Aucune frappe, donc aucune faute possible.

1. cPanel -> Gestionnaire de fichiers -> dossier public_html

2. ⚠️ AFFICHEZ LES FICHIERS CACHÉS : en haut à droite, bouton « Settings »
   -> cochez « Show Hidden Files (dotfiles) » -> Save.

3. S'IL EXISTE DÉJÀ UN .htaccess : clic droit dessus -> « Renommer » ->
   appelez-le  .htaccess-ancien-JJ-MM  (la date du jour).
   NE LE SUPPRIMEZ PAS. C'est lui qui dira ce qui n'allait pas.

4. Bouton « Téléverser » en haut -> choisissez le fichier
   htaccess-A-RENOMMER.txt que je vous ai envoyé.

5. Revenez dans public_html (« Retour »), puis cliquez « Recharger ».

6. Clic droit sur htaccess-A-RENOMMER.txt -> « Renommer » -> tapez exactement :

       .htaccess

   Avec le point devant, et rien d'autre. Si cPanel prévient que le fichier
   deviendra caché, acceptez.

7. Ouvrez https://chap.ci/ dans une fenêtre de NAVIGATION PRIVÉE.
   Le site doit s'afficher.


LES TROIS VÉRIFICATIONS
-----------------------
Toujours en navigation privée :

  1. https://chap.ci/
     La page d'accueil. Si elle s'affiche, le plus important est réglé.

  2. https://chap.ci/a-propos          (SANS le dièse)
     Une page simple, fond crème, « À propos de Chap.ci », vos deux noms.
     C'est la page que Google lira.

  3. https://chap.ci/.well-known/assetlinks.json
     Du texte, pas une page d'erreur. S'il affiche 404 avec une page blanche,
     c'est que l'empreinte de l'application manque côté serveur — un autre
     réglage, dites-le-moi.


SI LE SITE NE REVIENT PAS
--------------------------
Ne tentez rien d'autre : dites-le-moi immédiatement, avec ce que vous voyez
exactement à l'écran. La cause serait ailleurs et je reprendrais le
diagnostic depuis le début.
